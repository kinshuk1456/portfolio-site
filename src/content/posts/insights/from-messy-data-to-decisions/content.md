# From Messy Data to Real Decisions: What Dashboards Need

Most dashboards fail for a simple reason: they optimize for **coverage** (show everything) instead of **decisions** (make the next action obvious).

## A quick test
Before shipping, I ask:
- What decision will someone make in the first 2 minutes?
- What would change their mind?
- If a metric moves, do we know *who* owns the next step?

## The pattern I’ve seen in analytics + operations work
### 1) Start with the meeting
Dashboards are often used in a ritual (weekly review, morning standup). Design for that moment.

### 2) Define “health” vs “drivers” vs “details”
- **Health:** the state of the system
- **Drivers:** why it changed
- **Details:** where to investigate

### 3) Document the definition (or you’ll debate it forever)
The fastest way to lose trust is to change definitions silently.

## What I ship by default
- 4–8 KPIs max
- Clear owners and definitions
- A stable refresh cadence
- A “what changed since last week” view

## Closing thought
If someone can’t say what to do next after reading the dashboard, it’s not a dashboard — it’s a dataset.
